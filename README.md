# eval-report-shell

An optional renderer for Tiger Bot Eval batch reports. GPT may also write its own
layout. A report can use JSON and a commit-pinned script, or inline the script for
offline sharing:

```html
<script type="application/json" id="eval-report">{ ...report data... }</script>
<script src="https://cdn.jsdelivr.net/gh/YuremWu/eval-report-shell@<commit>/eval-report.js"></script>
```

The renderer keeps one overall donut, group bars, transcripts and source links.
Click donut segments to pin their panel; crossing other segments does not switch
it. Click another segment to switch, or dismiss outside / with Escape.
Group bars retain hover: red shows failed quotes and reasons, green the first
three supplied passed runs, in data order. Yellow keeps unknown cases separate.
Panels accept pointer entry, scrolling, source clicks, keyboard focus, Escape and
touch taps. Missing evidence is labelled, never generated by the renderer.

`runs` contains failed runs, `passed_runs` contains passed preview evidence, and
`unknown_runs` contains unknown evidence. Totals come from `batch` (`runs`,
`passed`, `failed`, `unknown`, `criterion`) and `group_stats` (the three status
counts per group), not from the number of supplied previews. Legacy reports with
only `runs` still render; missing group counts are labelled. Optional history
fields are unchanged. Quotes absent from the corresponding Tiger turn remain
unmarked and are listed as mismatches. The skill holds the complete data shape.

This public repository holds no report data. See `docs/planning/eval-report-hover.md`
in TheKeeper-ai/tiger-bot-test-eval for the approved change and acceptance scenarios.

## Verification

Open `tests/fixture.html` in a browser and run `await checkEvalReport()` in the
console. It uses synthetic cases to check preview limits/order, hover handoff,
scrolling, evidence jumps, keyboard behavior, unknown status, quote mismatches
and viewport bounds. Run `node --check eval-report.js` for syntax.
